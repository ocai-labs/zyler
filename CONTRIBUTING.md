# Contribute to Zyler's public resources

This repository contains downloads, documentation, examples, and templates.
The application source code is maintained privately; you do not need to build the
app to contribute here.

## Useful contributions

- Fix confusing or inaccurate instructions in `docs/`.
- Share a reusable Markdown template in `templates/`.
- Add a complete, small workflow example in `examples/` with import instructions.
- Report a reproducible bug or explain a workflow behind a feature request.

## Before opening a pull request

1. Keep the change focused and explain who it helps.
2. Check instructions against a published Zyler release and mention the version you used.
3. For a template or example, import the Markdown into Zyler and check the result.
4. Check relative links and include only material you have permission to share.
5. Use fictional or non-sensitive sample data. Remove private notes, credentials,
   personal file paths, and account details from files and screenshots.

Examples should explain how users can recreate links or setup steps. Avoid assuming
that importing multiple Markdown files automatically restores a linked vault.

For a substantial new guide or example, open an issue first to agree on its purpose.
For typos or small corrections, a pull request is enough.

Report vulnerabilities privately through [SECURITY.md](SECURITY.md).
